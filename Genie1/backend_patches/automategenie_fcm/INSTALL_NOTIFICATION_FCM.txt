5. From frappe-bench:

   After copying updated Python files, exit any existing console first:
   bench --site YOUR_SITE clear-cache
   bench restart
   bench --site YOUR_SITE console

   Run as Administrator/System Manager:

   from itgenie.fcm.fcm_utils import setup_fcm_notification_channel, validate_fcm_notification_installation
   validate_fcm_notification_installation()
   setup_fcm_notification_channel()
   frappe.db.commit()
   exit()

   Then run in the shell:

   bench --site YOUR_SITE clear-cache
   bench restart

   The setup helper appends FCM to the existing channel choices and exposes
   Subject/Message for FCM, preserving existing choices and conditions.
   Server Scripts must be enabled and a default queue worker must be running.
   If validation says the FCM controller is not active, review hooks/app order;
   another app may mask the override on either version. Do not remove other apps' behavior.

6. Example Notification:
   Enabled: checked
   Channel: FCM
   Document Type: Lead
   Send Alert On: New
   Subject: New lead: {{ doc.lead_name }}
   Message: Please contact {{ doc.lead_name }}.
   Recipients / Receiver By Document Field: lead_owner
   Condition: optional

   Normal Frappe Notification processing detects the event and evaluates the
   condition; our FCM channel handler queues delivery after commit. The generic
   Server Script renders Subject/Message and resolves recipients. fcm_utils
   checks enabled users, document access, active devices and alarm eligibility.
   This same channel integration follows Frappe's supported automatic triggers.
   Manual/custom broadcasts and Send Alert On = Custom remain excluded.

7. Existing behavior and limits:
   The old inline EVENT_ASSIGNED call was removed from mobile_site_visit.
   Deploy the updated frappe_server_scripts/mobile_site_visit_api.py to that
   existing Server Script. Event/participant/coordinate comment/ToDo creation,
   permissions and response keys remain intact. alarm_sent/alarm_queued remain
   false compatibility flags; this API no longer reports notification delivery.
   fcm_utils.py now accepts only generic DOCUMENT_NOTIFICATION payloads inside
   the trusted worker; the old Event-specific sender and payload were removed.
   Firebase project and recipient alarm role rules remain unchanged.
   Email/Slack/SMS/System channels delegate to their existing handlers.
   Sales User OR Designer recipients get alarm_enabled="1"; other enabled,
   authorized recipients receive a normal push with alarm_enabled="0".
   Generic calls outside the trusted worker context are rejected.
   Successful generic delivery acceptance is deduplicated per rule, document
   version and recipient for 24 hours, subject to Redis/Firebase failure limits.
   Firebase acceptance does not prove phone display or exactly-once delivery.
   Very large recipient groups need chunked dispatch before enabling them.
   Configure enabled FCM Notification rules for Event and Lead as needed.
   Event / New / Send To All Assignees resolves the committed ToDo assignments
   through the generic worker. Keep the hook/Server Script and Flutter generic
   handler available before relying on this new Event notification path.

8. Test on staging v15 and v16 with a disposable Lead and an enabled recipient
