SALES SUMMARY - DEPLOYMENT AND TEST SETUP
=======================================

Scope
-----
No new DocType, no document-triggered Notification rule, no generated files.
FCM recipients: enabled users with Sales Manager, Sales User or Designer.
Summary access: every logged-in, enabled user with the required Opportunity read
permissions. The three FCM roles do not restrict webpage/API access.
Counts: Opportunity.status equals Prospect or Pipeline, and any of
opportunity_owner, custom_field_owner_1, custom_field_owner_2 equals
frappe.session.user, with docstatus != 2 and normal Frappe read/User Permissions.
An Opportunity matching more than one owner field is counted once.
Counts are live when opened, not a historical snapshot at notification time.

6. Delivery and retry behavior
------------------------------
The scheduler queues one worker per enabled role recipient, grouping multi-role
users before paging. Each worker rechecks current enabled status/roles.
It creates one deterministic Notification Log per site/date/user with type Alert
and link /genie-sales-summary. No private counts are stored in push or log.
No token: the inbox item still exists (inbox_only). Failed push: log an error
without secrets; rerun the scheduler on the same date to retry failed recipients.
Firebase acceptance is recorded as an Info Comment on the Notification Log, so
same-day reruns skip accepted reminders. Keep these logs/comments for dedup.
A provider/network crash can be ambiguous: the Flutter receipt uses the stable
reminder ID to suppress repeated display/sound. Acceptance is not phone proof.
Jobs delayed until a different site date skip stale reminders.
The existing sender's active-device/latest-token policy is reused; no tokens,
device binding records or unrelated notifications are reset.

-----------------------

without Opportunity read permission. Compare counts to permitted Opportunity

  push tap -> Notifications -> View sales summary -> own live counts.
