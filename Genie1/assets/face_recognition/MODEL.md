## Input and output

Input `data` is float32 `[1, 3, 112, 112]`, RGB, channel first, with pixel values **0 through 255**. The graph itself subtracts 127.5 and scales by 1/128; do not divide by 255 or apply additional normalization outside the graph.

Output `fc1` is float32 `[1, 128]`. Validate dimension and finite values, then L2-normalize before storage/comparison. Never compare templates generated by different model/preprocessing versions.

ML Kit detects landmarks on the same upright JPEG decoded by the alignment worker. EXIF orientation is baked before detection. Five landmarks are fitted with a nonreflecting least-squares similarity transform and bilinear-warped to 112 by 112, with black border pixels. Target coordinates, in image-space order, match OpenCV's `FaceRecognizerSF.alignCrop`:

```text
eye left:    38.2946, 51.6963
eye right:   73.5318, 51.5014
nose:        56.0252, 71.7366
mouth left:  41.5493, 92.3655
mouth right: 70.7299, 92.2041
```

Preprocessing source: https://github.com/opencv/opencv/blob/4.x/modules/objdetect/src/face_recognize.cpp

## Pilot and deployment limits

The initial cosine threshold is **0.5**, a configurable pilot value. It is not a confidence percentage and is not a validated production accuracy guarantee. Calibrate both false accepts and false rejects using consenting employees, different employees, real camera devices, lighting, glasses, and replay attempts before broad deployment. Image brightness/sharpness and frontal/eyes-open checks also need real-device calibration.

Blink detection is an additional live-capture check, not full presentation-attack detection. Video replay and modified-client bypass remain possible with this Flutter/on-device and Frappe Server Script architecture. A server challenge stops replay of the API proof; it cannot independently establish that the phone executed the model.

Current maintainer licensing discussion: https://github.com/opencv/opencv_zoo/issues/318 . A maintainer points commercial on-device use to the Apache-2.0 license; detailed training-data provenance is not documented there. This manifest records the publisher's license declaration without inventing additional guarantees.

Runtime: `flutter_onnxruntime` 1.9.0 (ONNX Runtime Android 1.28.0), https://pub.dev/packages/flutter_onnxruntime . Android plugin calls run on its native background task queue; Dart decoding and alignment run in Flutter `compute`. Mobile recognition is local and requires no remote face inference service.
